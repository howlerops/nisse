# Wave 15 · Test and verification parity

PRD phase 7. A port is only trustworthy if the original tests run against it and real traffic gets the same answers. This wave makes both possible.

**Gate (with waves 14 and 18):** the tier 1 app's original tests run unmodified in spirit (translated, not rewritten), and the replay harness reports zero unexplained differences on a corpus of at least 10,000 requests.

## Test API parity

- [ ] **W15-01** Jest/Vitest-compatible API in `nisse test`: `describe`/`it`/`test`, hooks, `expect` with the common matchers, async tests, `.each`, `.skip`/`.only`, timeouts. Starts in Phase 6, because compat packages port their tests with it (W13-10).
  *Needs:* W5-07, W10-06. *Done when:* Jest's own matcher tests pass at ≥ 90%.
- [ ] **W15-02** Mocks: `jest.fn`/`vi.fn`, `spyOn`, module mocks as compile-time module substitution, fake timers on the event-loop executor.
  *Needs:* W15-01, W12-15. *Done when:* tests for each mock kind.
- [ ] **W15-03** Snapshot testing compatible with existing `.snap` files.
  *Needs:* W15-01, W12-20. *Done when:* an existing Jest snapshot file is read and matched.
- [ ] **W15-04** Supertest-style HTTP testing against an in-process server.
  *Needs:* W15-01, W12-09. *Done when:* Supertest's examples pass.
- [ ] **W15-05** Test translation in `nisse port`: Jest and Vitest test files and their config (`jest.config`, `vitest.config`, setup files) become `nisse test` suites.
  *Needs:* W15-01, W14-04. *Done when:* the tier 1 app's test suite translates and runs.
- [ ] **W15-06** Coverage reports mapped to `.nis` lines and, during migration, to the original `.ts` lines.
  *Needs:* W15-11. *Done when:* a coverage report opens against the original TypeScript files.
- [ ] **W15-11** Source maps chained TypeScript → Nisse → Go `//line`, so stack traces in ported apps can point at the original TypeScript line.
  *Needs:* W14-04, W4-23. *Done when:* a panic in a ported app reports the `.ts` location when asked.

## Verification

- [ ] **W15-07** HTTP record and replay: a recording proxy in front of the original Node app, a corpus of at least 10,000 requests generated by replaying the API collection with randomised data, replay against the ported binary, response diffs with ignore rules for volatile fields (timestamps, generated ids).
  *Needs:* W12-09. *Done when:* the replay report for the tier 1 app lists every difference as fixed or documented.
- [ ] **W15-08** Database state diffing after a replayed session, for apps whose responses don't show every write.
  *Needs:* W15-07. *Done when:* works for Postgres in the tier 1 setup.
- [ ] **W15-09** Differential fuzzing of built-ins against Node: random inputs to string, regex, number formatting, JSON and `Date` functions, comparing results.
  *Needs:* W10-32. *Done when:* runs nightly; findings fixed or listed as documented divergences.
- [ ] **W15-10** Performance comparison harness: the original on Node, the same API on Encore.ts (D-27), the original built with `bun build --compile`, and the port, for memory, throughput, p99 latency and startup time.
  *Needs:* W15-07. *Done when:* report generated for each reference port.
